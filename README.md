## Тема
Исключения в C#.
## Что реализовано
- ввод количества через TryParse;
- повторный ввод результатов после ошибок;
- обработка FormatException и OverflowException;
- проверка диапазона через throw и ArgumentOutOfRangeException;
- завершение каждой попытки через finally;
- сохранение корректных результатов и вывод статистики.
## Короткие ответы
1. С какой строки продолжается выполнение после обработанного исключения?
Ответ: выполнение продолжается со строки, которая идёт сразу после всей конструкции try–catch. Код внутри try после места ошибки пропускается.
2. Для чего нужен finally и почему он не заменяет catch?
Ответ: finally нужен для действий, которые должны выполниться при любом исходе — было исключение или нет. Он не заменяет catch, потому что сам не обрабатывает ошибку, а только выполняет свой блок.
3. Когда удобнее использовать TryParse вместо Parse с обработкой исключения?
Ответ: TryParse возвращает false вместо исключения, и повторный ввод проще сделать через обычный if в цикле. Parse с try/catch лучше там, где нужно различать конкретные типы ошибок.
